## 4. 词形还原库的选择与理由

| 候选 | 许可证 | 体积 | 结论 |
|---|---|---|---|
| **ECDICT exchange 字段 + 规则兜底**（采用） | MIT | 不增加依赖，映射表随词典打包 | 能处理不规则变化，并且和释义同源，查到的词元一定有释义 |
| ECDICT lemma.en.txt | 文件头声明“仅供研究和教育用途” | 2.3 MB | **许可证不明确，不使用** |
| compromise 14.18.0 | MIT | npm 解包 2,671 KB | 功能强，但对单个词不依赖上下文时，优势有限；体积大 |
| wink-lemmatizer 3.0.4 | MIT | 依赖 wink-lexicon，12,274 KB | 太大 |

任务书要求“选一个轻量、许可证合适的库”。我选择的是**数据加规则**的方式，没有引入第三方库。原因是：它满足“轻量”和“许可证明确”，并且在真实数据上的测试已覆盖 running/ran→run。如果你坚持必须使用独立的库，compromise 是首选替代方案，代价是内容脚本体积增加约数百 KB。

## 5. 已知问题与限制

- **词形还原不依赖上下文**：left 会归到 leave，saw 会归到 see，glasses 会归到 glass。词卡会同时显示原词自身的释义（如果词典有），但状态仍记在词元下。
- **字幕需要每个视频单独导入**：切换视频后会清空，不记住文件与视频的对应关系。
- **只支持 `www.youtube.com/watch`**：不支持 Shorts、嵌入播放器、移动版。
- **导出时间按“生成备份数据”记录**：如果用户在保存对话框中取消，扩展仍会认为已导出，提醒时钟会被重置。
- **Esc 不一定能关闭词卡**：按钮不获取焦点，按键通常到不了词卡，需要点 × 关闭。
- **词典数据不在仓库中**：新环境需要先运行 `npm run dict -- --download`。如果上游 ECDICT 改变，脚本会给出 SHA-256 不一致的警告。
- **ECDICT 第三方来源授权**：仓库整体是 MIT，但 README 提到部分词条来自其他词典来源，其授权链未逐一核查。这是我把词典数据排除在 Git 之外的原因之一。如果将来要公开发布，建议先做法律评估。
- **广告**：广告期间的时间属于广告，导入的字幕会按广告时间显示。

## 6. 追加：YouTube 字幕模式（方向二，2026-10-08）

**起因**：用户反馈导入示例文件后只看到四条字幕。示例文件本身只有四条通用测试字幕；真正的问题是用户没有与视频对应的字幕文件时，主链路无法使用。用户选择方向二。

**做法**：没有导入字幕文件时，读取 YouTube 播放器当前渲染的 CC 文字（页面 DOM），在叠加层中显示为可点击的单词，查词、标记、高亮与文件模式完全相同。

| 设计点 | 说明 |
|---|---|
| 优先级 | 导入的字幕文件优先；清除文件后回到 YouTube 字幕模式 |
| 开关 | 菜单“使用 YouTube 字幕（尽力而为）”和设置页复选框，默认开启 |
| 避免重复 | 本模式显示时把 YouTube 原字幕框设为透明（内联样式，可恢复）；关闭本模式、导入文件、切换视频或扩展卸载上下文时恢复原样 |
| 如实标注 | 字幕框左上角显示“YouTube 字幕 · 尽力而为”；不提供字幕列表和按句跳转；菜单说明“只读取当前显示的文字，没有完整时间轴” |
| 不使用私有接口 | 只读 DOM，不请求 timedtext，不读 Cookie |
| 生词标注 | 只为新出现的单词发送 `ll/annotate`，同一单词在一个视频内只查询一次 |

**验证**：新增 `tests/live-captions.test.ts`（4 个测试）和 `tests/overlay.test.ts` 中 3 个测试，覆盖读取与变化检测、CC 状态、原字幕框隐藏与恢复（包括 YouTube 重建字幕容器后再次隐藏）、文件与 YouTube 模式切换、开关持久化、切换视频后恢复。全部测试 161 个，连续运行 10 次均通过；类型检查通过；构建成功，`permissions` 仍为空。

**未验证**：真实 YouTube 页面上的全部行为，见 `docs/manual-test.md` C 节 Y1–Y10。特别是：
1. 字幕 DOM 的 class 名是否与测试中假设的结构一致。这是本模式最大的风险，YouTube 改版就可能失效。
2. 自动生成字幕逐词滚动时，文字频繁变化对点击的影响。
3. 把原字幕框设为透明后，YouTube 是否仍然持续更新其中的文字。

**已知限制**：
- 必须打开 CC；没有字幕的视频仍然只能导入文件。
- 只有当前一句，没有时间轴，不能按句回放，这符合任务书“不得宣称支持精确单句回放”的要求。
- 我们的字幕固定在播放器底部，不跟随用户拖动的位置，也不跟随 YouTube 字幕的字号和颜色设置。
- 对整个播放器子树做 MutationObserver 监听，性能影响尚未在真实页面测量。
